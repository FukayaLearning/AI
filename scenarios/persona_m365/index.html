    M365 Copilot 実践活用シナリオブック

    1. 本シナリオの前提・ターゲット環境

    本シナリオは、企業のセキュリティガバナンスやコンプライアンス要件により、外部LLMのAPI利用やローカル推論環境（GPU/CLIツール/自作スクリプト等）の構築が制限され、認可された Microsoft 365 Copilot および関連Office製品のみが利用可能な環境 を対象としています。

    想定環境と制約条件

    • 利用可能環境: Microsoft 365 Copilot (Enterprise / Business), Teams, Word, Excel, PowerPoint, Outlook, SharePoint
    • 主な制約:
    • IDE（VS Code等）や外部ターミナルからの直接API呼び出しは不可
    • 未認可の外部モデル・SaaSへの機密データ送信は遮断
    • 商用データ保護（Commercial Data Protection: CDP）のもと、テナント境界内でのみデータが保持される
    • 目指すゴール:
    • Officeアプリケーション内でのプロンプト技術を習得し、企画・ドキュメント作成・集計業務を高速化
    • SharePoint / OneDrive の社内ナレッジをGraphグラウンディングで高精度に引き出す

    2. モデル特性・動作原理の理解

    Microsoft 365 Copilotの背後では、最先端のフロンティアモデル（GPT-4o系モデル）と、社内データをリアルタイムに検索・関連付ける Microsoft Graph が連動して動作しています。

    flowchart LR
    User[ユーザーの入力<br>プロンプト] --> Graph[Microsoft Graph<br>社内ドキュメント・メール検索]
    Graph --> Context[関連コンテキスト結合<br>グラウンディング]
    Context --> FrontierLLM[フロンティアモデル<br>GPT-4o等]
    FrontierLLM --> AppResponse[Officeアプリ内での<br>回答・文書・数式出力]
    • フロンティアモデルの推論特性:
    • 詳細なベンチマークは Closed Weights ベンチマーク で解説されている通り、高度な日本語理解力・文脈把握力を持ちます。
    • ただし、社内固有の略称や背景情報を持たないため、「どの社内ドキュメントを参考にするか」「どのような役割・前提で出力するか」 をプロンプトで明示することが成否を分けます。

    3. Office アプリ別 実践レシピ

    3.1 Word: 仕様書・企画書のドラフト作成と推敲

    Word上のCopilotでは、新規文書の白紙状態からの構成案作成や、既存テキストのトーン調整に効果的です。

    • 新規仕様書の骨子作成:
    • 「〇〇システムの画面設計書のドラフトを作成してください。前提条件、画面遷移、入力バリデーション、エラーハンドリングの項目を含めてください。」
    • 文体統一と推敲:
    • 選択した文章に対して「敬体（です・ます調）に統一し、重複表現を省いて簡潔にリライトしてください。」と指示。

    3.2 Excel: データ集計・関数生成と分析

    Excel上のCopilotは、テーブル形式（Ctrl + T）で定義されたデータに対して最大の効果を発揮します。

    • 数式・関数の自動生成:
    • 「列C（売上）が前月比で10%以上向上しているレコードにフラグを立てるIF関数とXLOOKUP関数を組み合わせて新しい列を作成してください。」
    • データ傾向の要約:
    • 「この四半期の部門別売上トレンドを分析し、急成長しているカテゴリと減少傾向にあるカテゴリを抽出してください。」

    3.3 PowerPoint: 構成案からのスライド生成

    • Wordドキュメントからのスライド化:
    • OneDrive上に保存された仕様書や提案書（Word）を参照（/キーまたはファイル指定）し、「この提案書の要点を5枚のスライドで構成してください。」と指示。
    • スライドごとのスピーカーノート生成:
    • 各スライドの発表者原稿（想定質問への回答含む）を自動起草。

    3.4 Teams / Outlook: 会議録・メールの要約とAction Items抽出

    • Teams 会議文字起こしからの議事録作成:
    • 「本会議で決定した事項と、誰が何をいつまでに対応するかのアクションアイテム一覧を表形式で整理してください。」
    • 長文メールスレッドの要約:
    • 「このメールスレッドでの主要な論点と、未回答の質問事項を箇条書きで抽出してください。」

    4. 社内ナレッジ検索（グラウンディング）テクニック

    Copilotがテナント内のドキュメントを正確に参照するためには、以下の「見つけやすいドキュメント管理」と「明確な参照指示」が不可欠です。

    1. 参照ファイルの明示的指定:
    2. プロンプト入力時に /（スラッシュ）を入力し、対象となるWord/PowerPoint/PDFファイルを直接ピックアップしてグラウンディングさせる。
    3. 検索精度の高いドキュメント作成のコツ:
    4. ファイル名にプロジェクト名・日付・版数を明記する（例: 202608_AI導入要件定義書_v1.2.docx）。
    5. 見出し（Heading 1, 2, 3）を適切に設定し、ドキュメントの構造化を徹底する。

    5. 実践プロンプトテンプレート集

    日常業務で即座に活用できる構造化プロンプトのテンプレートです。

    【役割（Role）】
あなたはITコンサルタントのシニアアーキテクトです。

【前提・コンテキスト（Context）】
参照ファイル: /202608_新基幹システム要件定義.docx
対象読者: 社内の非エンジニア役員および業務部門長

【指示（Task）】
上記要件定義書の内容に基づき、役員向け説明用のサマリー（A4用紙1枚分）を作成してください。

【制約条件（Constraints）】
- 専門用語（API、マイクロサービス等）には平易な注釈を添えること
- 導入による「業務効率化効果」と「想定移行リスク」を明確に対比すること
- 重要な決定事項は箇条書き形式で記述すること

    6. トラブルシューティング & ハルシネーション抑制

    情報が古い・存在しないファイルを捏造（ハルシネーション）する場合の対処
    • 原因: 曖昧な質問に対して、Copilotが一般論で補完してしまうことが原因です。
    • 対策:
    • プロンプト末尾に「指定されたファイル内に記載がない情報は推測せず、『記載なし』と明記してください」と指示する。
    • 検索対象のSharePointフォルダやファイル名を直接指定する。
    回答が短すぎる・表面的な場合の対処
    • 「ステップバイステップで論理的に説明してください」「各項目について背景と具体例をそれぞれ100文字以上で記述してください」と深さを指定します。
